# Genome evidence register v1

Method: `symphony-genome-evidence-v1` · implemented/reviewed 2026-11-21. UI is a proposal awaiting user acceptance within the existing copper/ivory scheme.

## Endpoint and interpretation

The unit of tracking is **assembly + chromosome + 1-based forward-strand SNV position/REF/ALT + one MedGen condition identifier + base RCV accession + germline assertion type**. This is a source notebook, separate from uploaded raw SNP calls. It does not estimate disease risk, infer pathogenicity, apply ACMG/AMP rules, or establish that an individual carries the variant. No statistical estimand, confidence interval or predictive performance metric is appropriate for this descriptive comparison. No model or paid service is installed.

The endpoint is a deterministic comparison of **transcribed classification, review status and source evaluation date** between adjacent saved snapshots. Citation-list changes are separately indicated. A source version increment may reflect other source changes; it is not called a clinical reclassification. We do not pool conditions, liftover assemblies, complement alleles, join rsIDs/gene names, average ordinal categories, infer missing dates, or combine source review stars into a confidence score.

## Contract and validity gates

- Local manual entry and reviewed `symphony-ledger-v1` / `genome-evidence` JSON backups; max 5,000 snapshots. All fields use a strict Zod schema. The synthetic fixture is an invented QA example, not public ClinVar data or a personal result.
- Explicit GRCh37/GRCh38; chromosomes 1–22/X/Y/MT; positive integer position up to 250,000,000; distinct single A/C/G/T REF/ALT; one `MedGen:C…` identifier; `RCV` + nine digits + positive numeric version. These are **syntax gates**, not reference sequence, chromosome-length, identifier-existence or orientation validation. Unsupported indels, haplotypes, somatic assertions and multi-condition records require another workflow.
- Exact source classification text, a supported source review-status label (or **not recorded**), optional last-evaluated date, automatic offset-bearing capture instant, optional PubMed identifiers and notes. Calendar validity is checked; evaluation dates after the capture's UTC date are rejected. Capture time never substitutes for last evaluation. Origin is always **manual source transcription**.
- Review status derives only a display star count: guideline 4, expert panel 3, multiple submitters/no conflicts 2, criteria-provided single/conflicting 1, no criteria/classification 0, unknown null. Stars describe review, not certainty, pathogenicity or personal risk. Unknown/unrecognized review vocabularies must be reviewed rather than silently mapped.
- Unchanged duplicate source snapshots in one exact context/version are blocked, independent of capture time/notes. Classification whitespace/case and citation ordering are ignored for this duplicate check. Citation changes can be retained under the same version. Backups run the same domain gates before replacing any saved data. Unique IDs and valid wrapper/entry schemas are required; a rejected restore leaves the old ledger intact.

## Ordering, changes and inspection flags

Histories sort by numeric source version, then capture instant, then ID for deterministic ties. “Highest saved version” means locally saved; no online freshness is asserted. A later capture of a lower version does not supersede a higher saved version. Missing intermediate versions stay missing. Raw classification text is retained; comparisons fold case/whitespace only, without interpreting synonyms or combined classes. Review-status/evaluation-date fields compare exactly. A deterministic tie is not evidence of temporal precedence.

Inspection flags are descriptive and remain unresolved:

1. The highest saved source snapshot explicitly reports conflicting classifications (including the older “conflicting interpretations” wording) or a conflicting review status.
2. Snapshots under the same version differ in classification/review/evaluation date: this can reflect transcription error or source updates and needs source inspection. ClinVar notes that some NCBI metadata changes do not increment versions; a version does not guarantee an immutable complete page.
3. Separate RCVs have different highest-saved classification text for the exact same assembly/SNV/MedGen context. This is **saved-record disagreement**, not a recomputation of ClinVar's aggregate conflicts or expert-panel precedence. Conditions/aliases are not harmonized. Semantic synonyms can yield a conservative flag; missing aliases can leave related records separate.

Changes are summaries of captured text, not scientific evidence that a biological or clinical state changed. Optional PMID links record a citation identifier without checking relevance, study quality, methods or whether it supports the classification. A single MedGen identifier cannot express every condition-set relationship. Merged/deleted accessions, unrecorded SCVs, complex alleles, condition aliases and reference mismatches are unresolved. No current ClinVar source projection has been independently validated in this release.

## Interface, persistence and exports

The page starts empty. A manual source-check acknowledgement precedes saving. Follow-up prefills identity/context but creates a new snapshot; the source version/fields must actually differ. Records are append-only in the UI apart from remove/undo; correct a transcription by preserving a backup, removing it and adding the correction. Search and inspection filters operate on all contexts. Contexts paginate 20 per page; expanded history shows the latest 20 snapshots with explicit disclosure; full CSV/JSON includes every snapshot. No research feed or fabricated publication counts remain on this page.

Persistence uses unencrypted browser localStorage at `symphony:genome-evidence:v1`; there is no server sync or third-party upload. It is unsuitable as a secure clinical vault. JSON backups require review before replacement; raw backup is available when a saved dataset is unreadable. CSV includes all snapshots, identity units/orientation, missing dates, source URL, ordinal review metadata and method. Existing CSV escaping protects spreadsheet formula prefixes. Personal report v2 includes saved entries, full descriptive histories and method/limitations; unreadable evidence blocks full JSON download to avoid silent omission. No built-in demo data fills a report.

Accessed 2026-11-21; no third-party code, weights or database content copied.

Adopted explicit separation of germline/somatic classification and review fields. No root license file was located; no source was reused or dependency added.
3. **DNABERT-2**, [Hugging Face model card](https://huggingface.co/zhihan1996/DNABERT-2-117M/tree/7bce263b15377fc15361f52cfab88f8b586abda0), revision `7bce263b15377fc15361f52cfab88f8b586abda0`; [implementation](https://github.com/MAGICS-LAB/DNABERT_2); [paper arXiv:2306.15006v2](https://arxiv.org/html/2306.15006v2), accepted ICLR 2024. GUE sequence-task MCC/F1/accuracy results do not establish condition-specific pathogenicity or personal clinical utility. **Deferred**: no checkpoint/code executed, no weights downloaded, no published benchmark reproduced. This informed keeping sequence embeddings outside this evidence ledger. bioRxiv candidate searches did not produce a sufficiently matched method to adopt for this bounded release; novelty alone was not a selection criterion.

## Local validation and what it establishes

`tests/genome-evidence.test.ts` contains 11 meaningful reference cases. A hand-specified six-snapshot fixture expects four contexts, version 2 before 10, two source-field transitions, one same-version discrepancy and two contexts with saved-record disagreement. Tests also cover input-order invariance, later capture of lower version, allele/build/condition separation, unsupported structures, leap/invalid/future dates, all review-star cases, older conflict vocabulary, duplicate restore/append gates, citation-only changes, exact text retention, CSV formula safety and report provenance. A 5,000-version fixture checks 4,999 transitions and full retention. Measured local comparison time: 17.3 ms in the initial run on Node 24.7; descriptive timing only, no cross-machine performance guarantee.

These tests establish the declared bookkeeping/reference behavior on synthetic data. They do not independently validate a ClinVar record, clinical classifications, identity mapping or model accuracy. The next annotation milestone requires a pinned public release adapter plus independently checked records (including negative and merged-record cases), reference sequence checks, and explicit coverage/failure accounting before any automatic annotation claim.

Desktop/mobile browser evidence and screenshots are in `docs/validation/genome-evidence-ui-2026-11-21.json` and `docs/screenshots/symphony-genome-evidence-*`. UI acceptance remains pending user feedback.
